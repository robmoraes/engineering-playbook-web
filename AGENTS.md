# Repository Guidelines

## Project Structure & Module Organization

This repository is a Vue 3 + Quasar SPA that renders a build-time snapshot of
the `engineering-playbook` documentation. Application code lives in `src/`:
`components/` contains UI interactions such as search, `layouts/` defines the
application shell, `pages/` owns routed views, `router/` defines navigation,
and `content/` provides manifest/search access. Styling is in `src/css/`.

Content is generated by `scripts/sync-content.mjs` from the immutable revision
declared in `content-source.json`. Its outputs are
`src/content/generated/manifest.json`, `public/content/pages/`, and
`public/content/search-index.json`; regenerate them when content inputs or
generation logic changes. Container delivery configuration is in `Dockerfile`,
`docker/nginx/`, and `.github/workflows/`.

## Build, Test, and Development Commands

- `yarn`: install the Yarn 1.x locked dependencies.
- `yarn content:sync`: regenerate the static documentation payload and search index.
- `yarn dev`: start the Quasar development server.
- `yarn lint`: lint Vue and JavaScript/ES module source with ESLint.
- `yarn format`: apply Prettier formatting to supported project files.
- `yarn build`: synchronize content and compile the production SPA into `dist/spa/`.

Use `CONTENT_SOURCE_DIR=../engineering-playbook yarn content:sync` only for
local authoring; committed release candidates must use the pinned source ref.

## Coding Style & Naming Conventions

Use ES modules and Vue single-file components. Follow Prettier configuration:
single quotes, no semicolons, and a 100-character print width. Prefer
PascalCase for Vue components (`ContentSearchDialog.vue`) and kebab-case for
configuration or workflow filenames (`docker-image.yml`). Keep generated
content changes attributable to an intentional synchronization step.

## Testing Guidelines

There is currently no automated test suite; `yarn test` is a placeholder.
Before submitting changes, run `yarn lint` and `yarn build`. For content or
search changes, also run `yarn content:sync` and inspect the generated index
and relevant rendered route.

## Commit & Pull Request Guidelines

Use concise Conventional Commit messages, such as
`feat: add static content search modal` or
`fix: promote release digest with pinned content source`. Pull requests should
state the behavior changed, link the issue, list validation commands, and call
out generated content or Docker/release workflow impact. Include screenshots
for visible UI changes.

## Security & Release Notes

Do not add runtime GitHub fetching or expose Docker Hub credentials. Releases
must retain the pinned content revision and promote the existing
`sha-<commit>` image digest under the version tag rather than rebuild it.
